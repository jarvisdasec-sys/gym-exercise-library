# One-time setup for direct public blog posting

The contribution form writes directly to the BTB Supabase project. The Manus browser could not complete the Supabase sign-in, so the database has **not** been changed by this task. Open the project in your own signed-in browser: [Supabase project dashboard](https://supabase.com/dashboard/project/gjsgxtlzccrppehnzcgs).

In that project, open **SQL Editor**, create a new query, paste the complete contents of [`supabase/migrations/20261029000000_public_blog_posts.sql`](supabase/migrations/20261029000000_public_blog_posts.sql), then review and run the query. It is scoped to the `blog_posts` table and `btb-blog-images` storage bucket; it creates anonymous public read/insert policies for blog rows, no anonymous edit/delete policy, and a public JPEG/PNG/WebP bucket with a 5 MB object limit. Images are readable from the public URLs attached to posts, but the SQL does not add anonymous bucket-listing access. A restricted cleanup function can remove a newly uploaded image only if no post references it. It stores no email address or private contact field. New posts are public immediately and do not enter a review queue.

After the SQL completes successfully, tell me and I can publish the staged site update and check its live routes. The production contribution page will not change until the feature is deployed. Once deployed, you can optionally try the public form; any test contribution will be visible immediately and only a project owner can remove it. Because anonymous immediate posting is intentionally open, expect the possibility of spam or unsuitable content; this initial setup has no server-side rate limit or CAPTCHA and does not add a review queue.
